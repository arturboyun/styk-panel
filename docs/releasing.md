# Выпуск релиза

Для тех, кто собирает свою сборку или форк. Релиз идёт только по тегу, пуш в `main` ничего не выкатывает.

## Шаги

1. Поднимите `version` в `[workspace.package]` корневого `Cargo.toml`, выполните `cargo check` (обновит `Cargo.lock`), закоммитьте и запушьте.
2. Поставьте тег той же версии:
   ```bash
   git tag v0.2.0 && git push origin v0.2.0
   ```
3. [release.yml](../.github/workflows/release.yml):
   - проверяет, что тег совпадает с `Cargo.toml`;
   - собирает и тестирует `styk-panel` и `styk-agent` (musl) на нативных раннерах amd64 и arm64;
   - собирает фронт (tsc, lint, build, сжатие br/gz);
   - публикует мультиарх-образ `ghcr.io/<owner>/styk-panel` с тегами `vX.Y.Z`, `X.Y`, `latest` и делает smoke-тест;
   - в окружении `release` подставляет репозиторий, ключ и версию в `install.sh` и `styk`, собирает `SHA256SUMS`, подписывает его и создаёт GitHub Release.
4. Через пару минут после релиза панели увидят обновление (проверка раз в 6 часов, кнопка «Проверить» в настройках сразу).

## Ключ подписи

Релизы подписываются minisign. Публичная половина в [deploy/minisign.pub](../deploy/minisign.pub) встраивается в `install.sh` и `styk`, и уже установленные серверы принимают только релизы, подписанные этим ключом.

Для своего форка:

```bash
minisign -G -W -p deploy/minisign.pub -s ~/.config/styk-release/minisign.key
gh secret set MINISIGN_SECRET_KEY --env release < ~/.config/styk-release/minisign.key
```

- Ключ без пароля (`-W`): CI подписывает без интерактива.
- Окружение `release` ограничьте тегами `v*`, чтобы секрет не был доступен из веток и PR.
- Храните копию секретного ключа вне машины. Потеря ключа означает, что существующие серверы придётся переставить вручную: новый ключ они не примут.

## Совместимость

- Панель и агент обновляются вместе, но после отката могут встретиться разные версии: новые поля в `styk-proto` делайте `#[serde(default)]`, а методы не удаляйте за один релиз.
- Миграции базы только добавляющие. Если миграция ломает откат, напишите это в описании релиза.

## Проверить установку без публикации

```bash
scripts/local-release.sh dist v0.2.0                 # только amd64, подпись локальным ключом
docker save styk-panel:v0.2.0 > dist/image.tar       # IMAGE в таком релизе указывает на локальный тег
```

Тестовая машина: одноразовая VM или привилегированный контейнер Ubuntu 24.04 с systemd. Внутреннему Docker в таком контейнере нужен `{"features":{"containerd-snapshotter":false}}` в `/etc/docker/daemon.json`.

```bash
STYK_RELEASE_DIR=/root/dist bash /root/dist/install.sh panel --domain test.localhost --no-caddy
```

Что стоит прогнать: чистая установка, `styk doctor`, обновление на следующую версию, автоматический откат с заведомо битым образом, отказ при изменённом файле и битой подписи, `styk uninstall --purge`.
