# Обновление, откат и бэкапы

## Как узнать о новой версии

Панель раз в 6 часов спрашивает GitHub Releases (репозиторий из `STYK_UPDATE_REPO`, пусто отключает проверку). При новой версии в сайдбаре появляется метка, а в **Настройки → Версия и обновления** кнопка «Обновить». На сервере то же покажет `styk doctor`.

## Обновить

Из панели: кнопка «Обновить» (нужен sudo по TOTP, действие пишется в аудит). Панель просит агента запустить `styk update` отдельным systemd-юнитом `styk-update.service`, поэтому обновление не прерывается, когда перезапускается сама панель. Лог виден в той же карточке.

С сервера:

```bash
sudo styk update            # последний релиз
sudo styk update v0.2.0     # конкретный, в том числе более старый
```

Без терминала (cron, скрипт) добавьте `--yes`.

## Что делает обновление

1. Берёт блокировку: два обновления одновременно не идут.
2. Скачивает релиз, проверяет подпись minisign и сумму каждого файла. При ошибке ничего не меняется.
3. Если образ, агент и `compose.yml` совпадают с текущими, обновляет только CLI и выходит.
4. Сохраняет дамп базы в `/var/backups/styk-panel/...-preupdate-....dump`.
5. Запоминает прежние образ, `compose.yml` и версию в `/var/lib/styk` для отката.
6. Ставит новый агент (старый остаётся как `styk-agent.old`). Если новый не запустился, возвращает старый и останавливается.
7. Ставит новый `compose.yml`, закрепляет образ по digest в `STYK_IMAGE` и поднимает контейнеры, ждёт healthcheck до 3 минут.
8. Если панель не стала healthy, сам возвращает прежние образ, `compose.yml` и агент. Итог `failed` с причиной.

Итог последнего обновления: `styk status` (строка `update:`), полный лог: `styk logs update`.

## Откат

```bash
sudo styk rollback
```

Возвращает образ, `compose.yml` и агент, которые были до последнего успешного обновления. Откат на одну версию назад; дальше используйте `styk update vX.Y.Z` нужной версии.

База при откате не трогается. Если новая версия успела применить миграцию, несовместимую со старой (в changelog это будет написано отдельно), восстановите дамп `preupdate`, как описано ниже.

## Бэкапы базы панели

- Ежедневно: панель сама делает дамп через агента, хранит 14 дней. Отключается пустым `STYK_DB_CONTAINER=` в `.env`, если базу уже дампит ваш общий скрипт.
- Перед каждым обновлением: `...-preupdate-...`.
- Вручную: `sudo styk backup`.

Дампы лежат в `/var/backups/styk-panel` в формате `pg_dump -Fc`. Копируйте их за пределы сервера (restic, rclone и т.п.): локальная копия не спасёт от потери диска.

## Восстановить базу из дампа

```bash
cd /opt/styk-panel
sudo styk backup                               # страховка текущего состояния
docker compose stop panel
docker compose exec -T db pg_restore -U styk -d styk --clean --if-exists \
  < /var/backups/styk-panel/<файл>.dump
docker compose start panel
styk doctor
```

`STYK_SECRET_KEY` в `.env` должен быть тем же, что при создании дампа, иначе TOTP придётся сбросить всем: `docker compose exec panel styk-panel user reset-totp <логин>`.

## Перенос на другой сервер

1. На новом сервере обычная установка той же версии (`--version vX.Y.Z`).
2. Перенесите со старого сервера свежий дамп и из `/opt/styk-panel/.env` значение `STYK_SECRET_KEY` и свои настройки (Telegram, Cloudflare и т.п.). `POSTGRES_PASSWORD` оставьте новый.
3. Восстановите дамп, как выше, затем `styk restart`.
4. Переключите DNS и проверьте `styk doctor`.
